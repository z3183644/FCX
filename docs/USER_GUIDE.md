# FCX 用户指南

本文集中说明 FCX 的安装、兼容环境、主要功能、常见问题和故障排查。自动提交、自动开包和批量任务会执行不可逆的 EA 操作，第一次使用或升级后请先在低风险内容上验证设置。

## 安装与更新

### 支持环境

主要支持：

- Windows 10/11，或仍受 Apple 安全更新支持的 macOS 版本。
- 最新稳定版 Chrome 或 Edge。
- Tampermonkey。
- EA Ultimate Team Web App 桌面浏览器版本。
- 与用户脚本同一 Release 发布的 FCX 本地后端。

其他 Chromium 浏览器可能可用，但不逐一保证。移动浏览器、Safari、Firefox 和其他用户脚本管理器不属于主要支持范围。

用户脚本匹配：

```text
https://www.ea.com/ea-sports-fc/ultimate-team/web-app/*
https://www.easports.com/*/ea-sports-fc/ultimate-team/web-app/*
https://www.ea.com/*/ea-sports-fc/ultimate-team/web-app/*
```

### 安装用户脚本

1. 安装 Tampermonkey。
2. 从正式 GitHub Release 或维护者公布的渠道下载 `FCX.js`。
3. 停用或删除旧版 FCX、EAFC Auto SBC 等同类旧脚本。
4. 在 Tampermonkey 中打开并确认安装。
5. 确认只启用一份“一阵失心风FCX”。
6. 打开或刷新 EA Ultimate Team Web App。

同时启用不同版本可能重复创建入口、重复 Hook 页面或执行两份任务。

### 安装本地后端

1. 下载同一 Release 中与系统匹配的后端：Windows 使用 `FCX后端.exe`；Apple Silicon Mac 使用 `FCX后端-macOS-arm64.zip`；Intel Mac 使用 `FCX后端-macOS-x86_64.zip`。
2. Windows 使用 Release 提供的 `SHA256SUMS.txt` 核对文件；macOS 压缩包使用同名 `.sha256` 文件，可在下载目录运行 `shasum -a 256 -c <文件名>.sha256` 核对。
3. Windows 直接启动 EXE；macOS 解压后把 `FCX后端.app` 移到“应用程序”目录并打开，确认本地服务已启动。
4. 默认端口为 `8000`；修改端口后，FCX 设置必须填写相同端口。

macOS 版目前是未公证的开源构建。若首次打开时被 Gatekeeper 阻止，请在 Finder 中按住 Control 点击应用并选择“打开”，核对来源和 SHA256 后再次确认；不要关闭系统的全局安全检查。

本地后端只应在用户电脑运行，不要绑定公网地址、配置公网反向代理或转发端口。

### 更新

版本按钮只读取 `version.json` 并提示，不会自动下载或执行远程代码。更新时：

1. 停止正在执行的任务。
2. 下载并覆盖安装最新完整 `FCX.js`。
3. 如果公告要求，同时替换对应系统的 FCX 后端。
4. 刷新 EA Web App。

覆盖安装通常不会清除设置；清除 EA 站点数据、Tampermonkey 存储或浏览器配置可能删除设置和登录状态。

## 首次使用

首次加载需要阅读并确认免责声明。建议按以下顺序检查：

1. 打开“FCX设置”。
2. 确认本地后端端口。
3. 开启并检查球员保护。
4. 查看手动锁定球员。
5. 检查总评、价格和排除规则。
6. 使用低价值、可重复 SBC 做首次测试。

## 球员保护

### 手动锁定

球员详情中的锁定按 `definitionId` 保护卡型。锁定一张卡后，同一卡型的其他实例也不会用于 FCX SBC。

### 当前激活阵容

开启后，FCX 会在求解和提交前实时读取当前激活阵容，按实例 ID 保护其中球员。任务期间把球员加入当前阵容，也会在后续保护关口阻止旧方案提交。

当前阵容无法可靠读取时，FCX 会停止任务，不带风险继续。

### 进化球员

开启后，进化状态球员不会进入候选池。新生成的 DIY 进化球员在实体刷新后也应被识别。

### 三道保护关口

保护会在三个阶段执行：

1. 发送本地求解器前过滤候选。
2. 求解结果应用到 EA 阵容前复核。
3. 保存或提交前重新读取并检查。

## SBC 规则

### 总评范围

总评范围限制单张候选球员，不等于挑战要求的球队评分。默认范围为 `65–93`，部分青铜 SBC、推荐规则或用户保存的作用域可能不同。

规则优先级：

```text
单挑战设置 → 整组设置 → 内置推荐与全局交集 → 全局默认
```

### 价格范围

价格范围使用未折扣基础价值过滤球员。读不到可靠价格时不要设置，否则候选可能被排除或任务停止。

开启“忽略球员价值”后，本次任务不读取价格，也不应用价格范围；总评、排除和球员保护仍然有效。

### 只用普通卡

该规则只允许 EA `rareflag=0` 的非稀有卡进入候选池；总评等级仍受当前范围限制。挑战强制要求特殊卡时会提示规则冲突。

### 特殊分组保护

默认只限制挑战明确要求的特殊分组不要超量消耗，不限制挑战未点名的其他特殊卡。开启“允许额外消耗必需特殊卡”后，可以超过最低要求使用该分组。

手动锁定、当前阵容和进化保护始终优先。

### 排除规则

可以按国家、联赛、俱乐部、稀有度、交易状态、目标奖励、SBC 奖励等条件排除。仓库和重复球员只能在通过全部规则的候选中获得成本优惠，不能绕过规则。

## 普通 SBC

选择 SBC 后可以：

- 开始选中挑战。
- 开始整组 SBC。
- 设置执行次数。
- 临时忽略球员价值。
- 配置缺特殊卡自动补给。
- 配置爆仓自动清仓。
- 保存整组规则。

手动执行整组时，FCX 会先规划全部未完成挑战，再展示目标评分、实际评分、预计成本、使用球员、整组消耗和保护校验。用户可以临时排除实例并重新规划；确认前不会提交。

## 缺特殊卡自动补给

当目标挑战需要受支持的周黑或特殊分组，而当前合规候选不足时，可以先做指定补给 SBC：

1. 检测缺口。
2. 完成补给 SBC。
3. 开启本次准确奖励。
4. 处理球员挑选和未分配物品。
5. 刷新球员池。
6. 重试原目标。

未启用时，FCX 会记录具体缺口并跳过对应步骤。

## 永动机

永动机由可排序的 SBC 和开包步骤组成。

### 分段模式

按顺序执行各步骤，SBC 次数表示该段上限。

### 逐轮模式

按完整流程循环：

```text
A ×1 → B ×5 → 开包 ×2 → 下一轮
```

总轮数和步骤次数支持 `1–100` 与 `-1`。`-1` 表示持续执行或做到无解、耗尽、达到限制后进入下一步，仍受无进展、用户停止、EA 限流和安全保护。

无解通常是非致命步骤结果，后续步骤仍会继续；最终结果保留跳过原因。

### 求解失败自动做

每条永动机流程可以配置一个求解失败补偿 SBC。原步骤出现普通无解、候选不足、严格评分窗口无解或最低评分证明超时时，FCX 会先处理原步骤已经产生的准确奖励，再逐次完成补偿 SBC、开启其奖励并刷新球员池，最后只重试原步骤一次。

补偿次数支持 `1–100` 和 `-1`。缺周黑继续使用独立的周黑补给；次数耗尽、目标过期、EA 限流、提交失败、奖励失败和用户停止不会触发求解失败补偿。补偿 SBC 与当前失败 SBC 相同时不会执行，以避免递归。

## 卡包、挑选与未分配物品

### 准确奖励

SBC 任务只处理本次新增的准确奖励，不会因为仓库中存在同 ID 旧卡包而全部打开。

### FCX 开包

卡包页面的“FCX开包”是独立按钮：

- EA 原生开包保持可用。
- 每次只打开当前一个已拥有卡包。
- 继续使用自动挑选、未分配路由、收菜和总结。
- 尚未购买的金币或点数卡包不显示该按钮。

### 球员挑选

自动挑选支持按总评、按价格、同分优先非重复、恢复已打开未确认挑选，以及连续处理未分配挑选。价格不可用时按价格策略会回退总评。

关闭自动挑选后，任务会停在未分配页面。该页面的“自动挑选”按钮可以临时处理当前挑选，不修改保存的总开关。

### 未分配和爆仓

FCX 会尝试把物品分配到俱乐部、SBC 仓库、转会列表、快速出售或未分配保留。

只有 SBC 仓库无法接收不可交易重复球员时才触发爆仓清仓；转会列表已满不会误触发。清仓后没有释放位置时会停止并保留物品，避免死循环。

## 收菜、进化、历史与远控

### 收菜时刻

达到阈值、非重复且本次会话未处理过的球员可以触发记录和通知。通知或上传失败不应阻断开包、挑选主流程。

### DIY 特技进化

球员进化页面和球员详情“DIY进化”可以规划 PlayStyle 学院能力。应用前会检查实例、稀有度、位置、租借/限时状态、任务冲突和能力上限，并显示确认。

刷新失败不代表 EA 已成功应用的能力需要回滚；先切换页面或刷新 Web App 检查实体。

### 任务历史

任务历史按 persona 隔离，只保存在 IndexedDB，默认最多 100 条且最长 30 天。它记录状态、提交、开包、挑选、球员去向、SBC 消耗和停止原因；可以复制脱敏诊断信息。

### 账号与小程序

小程序远控是可选功能。本地 SBC 和大部分设置不要求登录 FCX 账号。使用远控时：

1. 在 FCX 设置注册或登录。
2. 小程序登录同一账号。
3. 保持 EA Web App、FCX 和本地后端运行。
4. 选择在线脚本设备。

远控只能调用脚本内置命令；完整球员池和本地求解请求不会上传到远程 FCX API。

## 结束任务

“结束任务”会发出取消请求。已经发送到 EA 的单次写请求不能强行撤回，FCX 会等待当前请求返回，再停止后续步骤。

显示“正在安全结束”时不要反复点击或刷新，除非长期无响应且确认 EA 没有待处理写操作。

## 常见问题

### FCX 是 EA 官方工具吗？

不是。FCX 是独立社区项目，与 Electronic Arts 没有隶属、赞助或授权关系。

### 为什么需要本地后端？

SBC 求解使用 OR-Tools CP-SAT。求解器在用户电脑运行，避免把完整球员池和求解请求上传到远程 FCX 服务。

### 可以不登录 FCX 账号使用吗？

可以。登录主要用于小程序远控和相关远程功能。

### 为什么脚本和 EXE 要配套？

部分版本会改变评分约束、优化目标或求解协议。脚本通过 `/health` 能力标识判断后端，不支持时会停止高风险任务。

### 为什么有时宁可停止也不重试？

只读请求可以安全重试。提交、开包、移动、出售和挑选确认属于写操作；如果无法确认上次是否成功，直接重试可能重复消耗。

### 为什么要求球队评分 83，却不接受 84 或 86？

求解器对最低球队评分使用严格窗口，并优先证明最低可行评分，避免为了价格更低而消耗明显更高的阵容。

### “忽略球员价值”安全吗？

它不会关闭三道球员保护，但会跳过价格过滤。未被保护的高价值球员仍可能被使用。

### 任务历史会上传服务器吗？

不会。任务历史只保存在浏览器 IndexedDB。

### 使用 FCX 会不会导致 EA 处罚？

自动化工具始终可能违反平台规则或带来账号风险。FCX 无法保证免受处罚，用户应自行了解规则并承担风险。

## 故障排查

### 收集诊断信息

先按 `F12` 打开 Console，在筛选框输入 `[FCX]`，清空后重新执行一次最小复现。记录：

```text
FCX版本：
FCX后端 /health：
EA Web App build：
浏览器版本：
Tampermonkey版本：
其他脚本/扩展：
功能入口与设置：
复现步骤：
第一条 [FCX] 错误：
```

不要公开粘贴 Token、Cookie、Authorization 头、persona ID 或完整球员池。

### FCX 入口没有出现

- 确认脚本启用、地址受支持且免责声明已确认。
- 确认没有同时启用多个 FCX 版本。
- 检查“显示自动 SBC 入口”等对应设置。
- 只启用 FCX 后刷新页面，排除其他脚本冲突。

FCX 不应主动把 EA 首页切到设置、自动 SBC 或球员进化，也不应通过手动搬动侧栏 DOM 修复入口顺序。

### 本地后端连接失败或版本过旧

访问：

```text
http://127.0.0.1:8000/health
```

检查 EXE 是否启动、端口是否一致、端口是否被占用以及防病毒软件是否拦截。涉及评分公式或求解能力的版本必须更换配套 EXE。

### 找不到求解方案

`INFEASIBLE` 表示发送给后端的候选和约束中无解，不代表账号里绝对没有球员。检查：

- 总评或价格范围是否过窄。
- 是否启用“只用普通卡”。
- 国家、联赛、俱乐部、稀有度等排除是否过多。
- 当前阵容、锁定或进化保护是否排除关键球员。
- 挑战是否要求特殊分组。
- 严格球队评分窗口内是否可行。

控制台 `candidate pipeline` 会显示各阶段候选数量。

### 手动 SBC 可以做，永动机不能做

检查步骤保存的 `setId`、名称、奖励类型和实时目标是否一致，以及步骤继承的规则和保护状态。FCX 不应为了匹配一个步骤扫描所有 SBC 挑战；流程目标失效时应更新在线流程或用户配置。

### EA 426 / 429 / 512 / 521

这些通常表示限流或 EA 临时服务异常。不要连续手动点击，也不要通过提高重试次数对抗持续限流。关闭重复脚本并等待冷却；如果 EA 原生页面也失败，等待 EA 恢复。

### 401 未授权

EA 401 通常表示 EA 登录会话失效，需要刷新 Web App 或重新登录。FCX 账号 401 与 EA 会话不同，应在设置中检查远程账号状态。明确 401 不应无限重试。

### SBC 446

可能是挑战、阵容或球员状态已变化。FCX 会先核验是否已经提交；状态无法确认时不盲目重试。持续出现时手动打开挑战，并提供挑战 ID 和第一条 446 日志。

### 开包 471 或卡包列表 500

471 常见于未分配物品阻塞。FCX 会尝试处理普通物品、球员挑选和分配，然后只重试开包一次。仓库或转会列表已满时需要手动处理。

卡包接口 500 会按设置重试；EA 原生商店也失败时应等待 EA 服务恢复。

### “FCX开包”没有出现

按钮只显示在“我的卡包”的已拥有卡包，不显示在金币或点数购买卡包。检查卡包底部原生操作区、其他 Store View 插件和 `[FCX][Pack]` 挂载日志。

### 球员挑选不自动进行

检查自动挑选开关、已打开未确认挑选、未分配阻塞和 EA `redeem`/确认请求状态。可以使用未分配页面的“自动挑选”临时处理。

### SBC 仓库已满

确认清仓 SBC 仍存在、有未完成挑战、目标 ID 未过期且次数可用。清仓后仓库没有减少时 FCX 会停止，避免死循环。

### 当前阵容读取失败或锁定球员异常

在 EA 中打开一次阵容页面并确认存在激活阵容。锁定按 `definitionId` 生效，确认详情和设置列表一致、persona 未切换且站点存储未被清除。

保护数据无法可靠读取时，不应绕过错误继续提交。

### 任务结束后无法重新读取

日志显示“请求已取消”时，可能是取消状态泄漏到页面刷新请求。等待遮罩完全释放，手动刷新自动 SBC 页面；仍失败时刷新 Web App，并提供取消前后的第一条 `EaRequestError`。

### 显示 0 球员总结

无提交、开包、挑选或获得球员时，应显示“任务未完成”和具体原因。若仍出现空总结，请提供永动机步骤名、`Solver status`、停止原因及是否有后续步骤成功。

### DIY 进化结束后遮罩不消失

先检查 EA 球员是否已经获得能力，不要立刻重复应用。切换页面或刷新 Web App，并提供最后一段 `[FCX][EVO]` 日志。

### 版本或在线流程读取失败

`version.json` 或 `routines.json` 失败不会阻止核心功能。流程目录会回退脚本内置快照，且不会执行远程 JavaScript。g.co、字体预加载和 EA 图片 preload 警告通常与 FCX 无关。

## 报告问题

普通问题使用 GitHub Issue。请说明环境、设置、最小复现和第一条 FCX 错误；安全问题按 [安全策略](../SECURITY.md) 私下报告。

项目通常不提供 EA 账号申诉、第三方脚本维护、绕过限流或验证码、远程控制用户电脑，以及索取账号凭据等支持。
